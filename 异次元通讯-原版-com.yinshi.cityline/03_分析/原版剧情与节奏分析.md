# 原版《异次元通讯》v1.0 剧情数据与节奏分析

样本：`01_原始/异次元通讯-v1.0-962.apk`（`com.yinshi.cityline`，versionName 1.0，9,924,566 字节，原生 Android，minSdk 14 / targetSdk 19）。

## 1. 数据结构

- 剧情文件：`assets/story.txt`，UTF-8 JSON，215398 字符，顶层 `{chapters, version}`；`chapters` 261 个节点，共 **966 行**，824 条不同文本，最长 44 字。
- 每行字段：`chapterId / option1 / option1GotoChapterId / option2 / option2GotoChapterId / text / busyWaitTime / showTime / isNewData / pictureResourceId / contentType`。
- `contentType`：NPC 消息=857、系统/状态=103、玩家选项=3、玩家消息=3。
- 节点 id 是数字串（1, 7, 11, 14, 19, 24 … 1220，末尾还有一个 `AAA`），**分支靠 `*GotoChapterId` 指向目标节点**，与重置版的 `选项N / 分支N` 标签模型同构。

> 说明：这份 `story.txt` 只覆盖**第一章**（261 个节点）。原版其余章节由服务器下发，APK 里没有缓存。

## 2. 节奏：`busyWaitTime`

每条消息自带一个「对方输入中」的毫秒数，共 966 条，取值 200 – 14400000 ms：中位 **2400 ms**、p25 1600、p75 3600、p90 4800。

对 ≤60 秒的 924 条按字数做最小二乘：**`wait_ms ≈ 523 + 175.0 × 字数`**（r = 0.378）。即约 0.5 秒起步、每字 0.175 秒：

| 字数 | 2 | 5 | 10 | 20 | 40 |
|---|---|---|---|---|---|
| 估算 | 873 ms | 1398 ms | 2273 ms | 4023 ms | 7523 ms |

最常见的取值：1000 ms ×87、2000 ms ×64、2200 ms ×62、1600 ms ×54、2400 ms ×50、1800 ms ×47、3000 ms ×43、1200 ms ×37。

另有 42 条 **>60 秒的「离线等待」**（对方下线）：2 分、3 分、5 分、10 分、30 分、1 小时、2 小时、4 小时。

> 这解释了「原版并没有这么快」：原版平均一条消息要等 2–3 秒，长句 5–7 秒，而不是即时弹出。

## 3. 与重置版的文本保真度

- 原版第一章唯一文本 **824** 条；重置版第一章 1225 行（1068 唯一）。
- **逐字相同 589 条**：占原版 71.5%，占重置版 55.1%。
- 剩下 235 条是改写或标点差异，节选（原版 → 重置版最相近的一句）：

  - `(*・・*)` → （无相近）
  - `(￣y▽￣)` → （无相近）
  - `0` → `803`
  - `2` → （无相近）
  - `2035是那个房间！` → `2035是哪个房间`
  - `2333333333` → `要不试试23333？`
  - `3` → `803`
  - `31303` → `303`
  - `42号门……42号门` → （无相近）
  - `42号门不就是……刚才我经过的！` → `42号门不就是刚才我经过的吗`
  - `5` → （无相近）
  - `89页不见了！你看，就是这样！` → `89页不见了！`
  - `89页被撕了，现在剩下的是88页和91页…` → `89页被撕了，现在剩下的是88页和91页...`
  - `R—U—N` → （无相近）

> 结论：开头几屏几乎一字不差（`对方已上线`、`喂！有人看得到吗？`、`有人在线吗？`、`喂喂！有人吗？`），越往后改写越多；重置版还统一了省略号（`…` → `...`）、去掉了「Miko酱」等称呼。

## 4. 与重置版的字段对应

| 原版 | 重置版 CSV | 说明 |
|---|---|---|
| `text` | 第 2 列 | 文本 |
| `contentType=0` | `左` / `右` | NPC / 玩家消息 |
| `contentType=4` | `中` | 系统状态（上线/下线/词典解锁…） |
| `option1/2` + `GotoChapterId` | `右,选项,N` | 选项与其目标块 |
| `busyWaitTime` | （无） | 原版逐条计时；重置版只保留分钟级 `等待` |
| `pictureResourceId` / 文本前缀 `imageN&` | `动态` / `图鉴` | 原版把配图编号塞进文本前缀 |

`imageN&` 前缀实例：`image1&我这里能看到星星，你呢` —— 原版用「文本前半截写图片编号」的方式带图，重置版改成了独立的 `动态` 指令。
